Chapter 9: How Do We Locate Disease-Causing Mutations?

Chapter 3 built a genome out of reads. This chapter starts from a genome that is already known and places reads on it. The input is a reference sequence of three billion nucleotides and a billion short strings taken from a patient, and the output is the position of each string in the reference. Every structure in the chapter solves that problem, and each one appears because the previous one does not fit in a machine.

Reading a Patient's Genome

Ohdo syndrome is a rare inherited developmental disorder. Several different genes cause forms of it, and one form, the Say-Barber-Biesecker-Young-Simpson type, is caused by mutations in a gene called KAT6B on human chromosome 10. A patient arrives with the disorder and without a diagnosis, and the question is which position of which chromosome differs from what it should be.

A gene is a stretch of a chromosome that codes for a protein, and a mutation is a difference between the sequence a patient carries and the sequence carried by most people. The commonest kind is a single nucleotide polymorphism, or SNP, in which one nucleotide is replaced by another. Any two people differ at millions of positions and almost all of those differences are harmless, so the work is not to find differences but to find the one difference that matters.

Sequencing the patient produces reads, and Chapter 3 turned reads into a genome. That is the wrong tool here. Assembly from error-prone reads is expensive, and it stops at contigs rather than at whole chromosomes, so the answer would still have to be lined up against something before any difference could be read off. A reference human genome already exists. Placing the patient's reads directly on it is cheaper, and it produces the comparison as its output rather than as an extra step.

Read mapping is that placement: given a reference and a collection of reads, find where each read belongs. Once every read sits at a position, each position of the reference carries a column of nucleotides, one per read covering it. A column where the reads agree with the reference says nothing. A column where they disagree is a mutation, and a column split in two says the patient carries the difference on one copy of the chromosome and not the other.

Multiple Pattern Matching

Multiple Pattern Matching Problem. Given a string $\textit{Text}$ and a collection $\textit{Patterns}$ of shorter strings, find all starting positions in $\textit{Text}$ where a string from $\textit{Patterns}$ occurs.

The direct method takes one pattern at a time and slides it along the text, comparing at every position. A pattern of length $k$ costs $O(|\textit{Text}| \cdot k)$, and the whole collection costs $O(|\textit{Text}| \cdot \sum_i |\textit{Pattern}_i|)$. Both factors are large here. A human genome is about $3.1$ billion nucleotides, and an experiment that reads every position thirty times over with reads of length $100$ produces about $930$ million of them.

Measuring the rate makes the size of that product concrete. Searching a real $100$ kb window of human chromosome 10 for $300$ patterns of length $30$ by direct comparison takes $7.13$ seconds. The genome is $31{,}000$ times longer than that window and a real experiment has $3.1$ million times as many patterns, so the same code on the real problem would run for about $6.8 \times 10^{11}$ seconds, which is twenty-one thousand years.

Nothing in that estimate is wasted on a bad constant. The cost is the product of two large numbers, so the only way out is to stop paying one of them, and there are two ways to try. Preprocess the patterns into a structure that matches all of them in one pass over the text, or preprocess the text into a structure that answers a pattern without looking at the text at all.

The Trie

A trie is a rooted tree whose edges carry single symbols, in which no node has two outgoing edges with the same symbol, and in which each pattern of the collection is spelled by the symbols along the path from the root to some leaf. Patterns that begin the same way share the beginning of their path, so the shared prefix is stored once. Building it is one walk per pattern, creating an edge whenever the symbol needed is missing. 

def trie_construction(patterns):
    trie = {0: {}}
    for pattern in patterns:
        node = 0
        for symbol in pattern:
            if symbol not in trie[node]:
                child = len(trie)
                trie[node][symbol] = child
                trie[child] = {}
            node = trie[node][symbol]
    return trie

The trie is a dictionary from node number to a dictionary from symbol to child, so the root is node $0$ and a leaf is a node whose dictionary is empty. Node numbers are handed out in the order the nodes are created, which is why len(trie) is the next free number.

Matching starts at a fixed position of the text and walks down. At each step there is at most one edge to follow, because no node repeats a symbol, so no search or backtracking is involved. Reaching a leaf means a whole pattern has been spelled and therefore occurs at the position the walk started from. Running out of matching edges means no pattern starts there. 

def prefix_trie_matching(text, trie, start):
    node, i = 0, start
    while True:
        if not trie[node]:
            return text[start:i]
        if i == len(text) or text[i] not in trie[node]:
            return None
        node = trie[node][text[i]]
        i += 1


def trie_matching(text, patterns):
    trie = trie_construction(patterns)
    return [i for i in range(len(text)) if prefix_trie_matching(text, trie, i)]

This is already better than the direct method. Building the trie costs one step per symbol of the input, and the search costs $O(|\textit{Text}| \cdot \ell)$ where $\ell$ is the length of the longest pattern, with no dependence on how many patterns there are. The direct method paid for every pattern separately; the trie pays for the longest one.

Its size is the problem. Two random reads of length $100$ agree on their first few symbols and then diverge, so almost nothing is shared. Building the trie of $100{,}000$ real reads of length $100$ taken from the Escherichia coli genome gives $9{,}223{,}868$ nodes for $10{,}000{,}000$ symbols of input, which is $92$ percent of the symbols stored separately. Scaled to the $930$ million reads of a human experiment that is about $8.6 \times 10^{10}$ nodes, and a node holding even a few bytes puts the structure far beyond the memory of any machine.

There is a second objection that no amount of memory would fix. The reads change with every patient and the reference does not, so a structure built from the reads has to be rebuilt from nothing for each new sample, and the whole genome has to be walked again. The fixed object is the reference. It is the one worth preprocessing.

The Suffix Trie

Every occurrence of a pattern in a text is a prefix of some suffix of that text, and that observation turns matching into a lookup. Store all $|\textit{Text}|$ suffixes in a trie, and a pattern occurs in the text exactly when it can be spelled from the root. The suffix trie is that structure, and it is the trie of the suffixes and nothing more.

A terminal symbol is appended to the text first, written $\$$ and chosen to be smaller than every symbol of the alphabet and to occur nowhere else. Without it a suffix can be a prefix of another suffix and would end in the middle of a path; with it every suffix ends at a leaf of its own. The construction records, alongside each child, the position in the text of the symbol on the edge, which the next section needs. 

def suffix_trie(text):
    trie = {0: {}}
    for start in range(len(text)):
        node = 0
        for i in range(start, len(text)):
            if text[i] not in trie[node]:
                child = len(trie)
                trie[node][text[i]] = (child, i)
                trie[child] = {}
            node = trie[node][text[i]][0]
    return trie

The cost of a search has changed shape. A walk down the suffix trie takes one step per symbol of the pattern and stops, so it costs $O(|\textit{Pattern}|)$ and does not depend on the length of the text at all. Searching a $100$ kb reference for a pattern of length $30$ and searching a $10$ kb reference for the same pattern take, measured, $49.8$ and $48.2$ microseconds. That is the property the whole chapter is buying, and every structure that follows keeps it.

The size is now hopeless in a different way. The suffix trie has one node per distinct substring of the text, plus the root, and a text of length $n$ has $\Theta(n^2)$ substrings. Counting them exactly for the real E. coli genome, which is $4{,}641{,}652$ nucleotides long, gives $10{,}772{,}390{,}977{,}166$ nodes: nearly eleven trillion nodes for a genome of four and a half million symbols, and E. coli is six hundred times smaller than a human genome.

The figure shows where the waste is. Most nodes have exactly one child and sit on a path that branches nowhere, carrying one symbol each when the whole path could carry one string.

The Suffix Tree

The suffix tree is the suffix trie with every non-branching path replaced by a single edge labelled with the whole string along that path. The label is not stored either. An edge keeps a pair, the position in the text where its string starts and its length, so an edge costs two integers no matter how long its label is. 

def suffix_tree(text):
    trie, tree = suffix_trie(text), {}

    def collapse(node):
        tree[node] = []
        for child, position in trie[node].values():
            length = 1
            while len(trie[child]) == 1:
                (child, _), = trie[child].values()
                length += 1
            tree[node].append((child, position, length))
            collapse(child)

    collapse(0)
    return tree

Theorem. The suffix tree of a text of length $n$ ending in a terminal symbol has at most $2n - 1$ nodes.

The proof counts edges twice. The terminal symbol occurs once and is smaller than everything else, so no suffix is a prefix of another suffix, so each of the $n$ suffixes ends at a leaf of its own and there are exactly $n$ leaves. Every internal node has at least two children, because a node with one child was collapsed into its parent's edge. Writing $I$ for the number of internal nodes, the edges leaving internal nodes number at least $2I$, and a tree on $n + I$ nodes has exactly $n + I - 1$ edges, so $n + I - 1 \geq 2I$ and $I \leq n - 1$. The total is at most $2n - 1$. The bound counts nodes and says nothing about how many bytes a node costs, which is where the trouble returns.

Measured on the E. coli genome the tree has $4{,}641{,}653$ leaves and $2{,}979{,}546$ internal nodes, $7{,}621{,}199$ in total, or $1.64$ nodes per nucleotide. Eleven trillion has become seven and a half million.

The construction above builds the trie first, so it costs $\Theta(n^2)$ time and $\Theta(n^2)$ space and cannot be run on a genome. Suffix trees can be built in $O(n)$ time and $O(n)$ space by the algorithms of Weiner and of Ukkonen, which grow the tree one suffix at a time while keeping shortcut links between nodes that spell strings differing by their first symbol. That machinery is not reproduced here, and none of what follows depends on it.

The Longest Repeat

An internal node of the suffix tree spells a string that is followed by at least two different symbols in the text, so that string occurs at least twice. A leaf spells a string that occurs once. The longest repeated substring is therefore the string spelled by the deepest internal node, measured in symbols rather than in edges. 

def tree_walk(tree, text):
    """Yield (node, label) for every node of the suffix tree."""
    stack = [(0, '')]
    while stack:
        node, label = stack.pop()
        yield node, label
        for child, position, length in tree[node]:
            stack.append((child, label + text[position:position + length]))


def longest_repeat(text):
    tree = suffix_tree(text + '$')
    internal = (label for node, label in tree_walk(tree, text + '$') if tree[node])
    return max(internal, key=len)

Run on the real E. coli genome, this returns a repeat of $2{,}815$ nucleotides, occurring exactly twice, at positions $4{,}168{,}619$ and $4{,}210{,}021$. The two copies are the 23S ribosomal RNA gene, carried by the rrlB and rrlE operons. Ribosomal RNA is needed in quantity, so the cell keeps several identical copies of the gene, and the longest exact repeat in the genome is one of them.

Two Strings at Once

Comparing two texts uses one tree built from both. Join them with a separator that occurs nowhere else, build the suffix tree of the join, and colour each leaf by which of the two strings its suffix begins in. Colour every other node by what lies below it: a node with only one colour below it takes that colour, and a node with both takes a third, purple. A purple node spells a string that occurs in both inputs. 

def colour_tree(tree, text, cut):
    """Colour every leaf by the string its suffix starts in, every internal
    node by its children: red, blue, or purple when both are below it."""
    colour = {}

    def paint(node, depth):
        if not tree[node]:
            colour[node] = 'red' if len(text) - depth < cut else 'blue'
        else:
            below = set()
            for child, _, length in tree[node]:
                below.add(paint(child, depth + length))
            colour[node] = below.pop() if len(below) == 1 else 'purple'
        return colour[node]

    paint(0, 0)
    return colour


def longest_shared_substring(text1, text2):
    text = text1 + '#' + text2 + '$'
    tree = suffix_tree(text)
    colour = colour_tree(tree, text, len(text1))
    shared = (label for node, label in tree_walk(tree, text) if colour[node] == 'purple')
    return max(shared, key=len)

No purple node can spell a string containing the separator. Only one suffix has the separator at any given offset from its start, so a string containing it is a prefix of exactly one suffix, so the node spelling it is a leaf and not a branching node. The colouring therefore needs no special case for strings that straddle the join.

The shortest string that appears in one text and not the other comes off the same coloured tree. Take a purple node, whose string does occur in both, and an edge from it to a node that is red, meaning nothing below that edge comes from the second text. The purple node's string followed by the first symbol of that edge occurs in the first text and not in the second, and it is one symbol longer than a string that occurs in both, so no shorter answer can be built at that node. 

def shortest_non_shared_substring(text1, text2):
    text = text1 + '#' + text2 + '$'
    tree = suffix_tree(text)
    colour = colour_tree(tree, text, len(text1))
    candidates = []
    for node, label in tree_walk(tree, text):
        if colour[node] != 'purple':
            continue
        for child, position, _ in tree[node]:
            if colour[child] == 'red' and text[position] not in '#$':
                candidates.append(label + text[position])
    return min(candidates, key=len)

What stops the suffix tree from being the answer to the chapter is the constant factor. A node holds a child list, a parent, and the two integers on its incoming edge, which is about $20$ bytes in a careful implementation. At $1.64$ nodes per nucleotide, a human genome gives roughly $101.68$ gigabytes. The structure is linear in the genome and still does not fit in a machine.

The Suffix Array

The suffix array keeps the order the tree imposed and throws away the tree. It is the list of starting positions of all suffixes, sorted by the suffixes themselves, and it is $n$ integers. 

def suffix_array(text):
    return sorted(range(len(text)), key=lambda i: text[i:])

That one line costs $O(n^2 \log n)$, because each of the $O(n \log n)$ comparisons compares strings of length up to $n$, and the keys themselves take $\Theta(n^2)$ space. It is the definition rather than the method. Suffix arrays are built in $O(n \log n)$ time by sorting on prefixes of doubling length, and in $O(n)$ time by algorithms that recurse on a subset of the positions; the E. coli array used for the measurements in this chapter was built by the doubling method in $190$ seconds.

Searching is binary search. The suffixes beginning with the pattern are consecutive in sorted order, so the occurrences form one contiguous block of the array, and its two ends are found by comparing the pattern against the first $|\textit{Pattern}|$ symbols of a suffix. 

def suffix_array_matching(text, pattern, array):
    def bound(past):
        """The first row whose prefix is at least the pattern, or past it."""
        low, high = 0, len(array)
        while low < high:
            middle = (low + high) // 2
            prefix = text[array[middle]:array[middle] + len(pattern)]
            if prefix < pattern or (past and prefix == pattern):
                low = middle + 1
            else:
                high = middle
        return low

    return sorted(array[bound(False):bound(True)])

Each probe costs up to $|\textit{Pattern}|$ symbol comparisons and there are $\log_2 |\textit{Text}|$ probes, so a search costs $O(|\textit{Pattern}| \log |\textit{Text}|)$. That is worse than the suffix tree's $O(|\textit{Pattern}|)$ by the logarithmic factor, and the trade is worth it: four bytes per nucleotide gives $12.4$ gigabytes for a human genome instead of $101.68$. It is a factor of eight, and it is still more memory than the machine doing the mapping is likely to have.

The Burrows-Wheeler Transform

The next structure was invented for compression rather than for search. Run-length encoding replaces a run of identical symbols by the symbol and a count, so it shrinks a string in proportion to how long its runs are. Genomes have almost no runs, so run-length encoding does nothing to them directly. The Burrows-Wheeler transform is a reordering of the symbols of a string that creates runs where the string has repeats, and it is reversible, which is what makes it usable as a compression step.

Form all cyclic rotations of the text, sort them, and read off the last column. Sorting the rotations groups together the rows that begin the same way, and rows that begin the same way tend to be preceded by the same symbol, so the last column collects equal symbols next to each other. 

def burrows_wheeler(text):
    matrix = sorted(text[i:] + text[:i] for i in range(len(text)))
    return ''.join(row[-1] for row in matrix)

The matrix is never built by a real implementation, and it does not have to be. Because the terminal symbol is unique and smallest, sorting the rotations sorts them by the suffix that begins each one, so row $i$ of the matrix begins at position $\textit{array}[i]$ of the text and the last symbol of that row is the one just before it. The transform is one line away from the suffix array: 

def burrows_wheeler_from_array(text, array):
    return ''.join(text[i - 1] for i in array)

How much this buys depends entirely on the sequence, and measuring it on real DNA gives an honest and uneven answer. A megabase of the E. coli genome has runs of mean length $1.353$, and its transform has runs of mean length $1.408$. A $100$ kb window of human chromosome 10 goes from $1.429$ to $1.447$. Both are almost nothing, because a bacterial genome and an ordinary human gene region are close to random over four letters and have few long repeats to convert. A $100$ kb window of the centromere of human chromosome 1, which is satellite DNA built from a repeating unit, goes from $1.390$ to $12.62$. The mechanism is real and it pays in proportion to repetition.

Inverting the Transform

The transform keeps only the last column, and the first column is recovered from it for free by sorting, since both columns hold the same multiset of symbols. Recovering the rest of the text rests on one fact about the two columns.

First-Last Property. The $k$th occurrence of a symbol $c$ in the first column and the $k$th occurrence of $c$ in the last column are the same occurrence of $c$ in the text.

The proof compares two sorted lists. A row beginning with $c$ has the form $c\,w$, and the rows beginning with $c$ appear in the matrix in the order their $w$ parts sort, since the leading $c$ is shared. A row ending with $c$ has the form $w\,c$, and because the rows are rotations of one string, $w\,c$ is a row exactly when $c\,w$ is a row, with the same $w$. All rows have the same length and are distinct, so comparing $w\,c$ against $w'c$ compares $w$ against $w'$, and the rows ending with $c$ also appear in the order their $w$ parts sort. The two lists are indexed by the same $w$ in the same order, so their $k$th entries carry the same occurrence of $c$.

Following the correspondence from the last column to the first therefore moves one position backwards through the text. Starting at row $0$, the row beginning with the terminal symbol, and following it $n$ times visits every position of the text in reverse. 

def last_to_first(transform):
    first = sorted(range(len(transform)), key=lambda i: (transform[i], i))
    mapping = [0] * len(transform)
    for row, i in enumerate(first):
        mapping[i] = row
    return mapping


def inverse_burrows_wheeler(transform):
    first, mapping = sorted(transform), last_to_first(transform)
    row, text = 0, []
    for _ in range(len(transform)):
        text.append(first[row])
        row = mapping[row]
    return ''.join(reversed(text))

Pattern Matching with the Transform

The same correspondence searches. The rows whose first column begins with a given string are consecutive, exactly as in the suffix array, so a search maintains a band of rows and shrinks it one symbol at a time. The pattern is consumed from the right, because the last column holds the symbol that precedes each row and prepending is what the correspondence supports.

At each step the band holds the rows beginning with the part of the pattern matched so far. The rows of the band whose last column holds the next symbol to the left are the ones that survive, and following the correspondence sends them to the new band. When the pattern runs out, the height of the band is the number of occurrences. 

def bw_matching(transform, pattern):
    mapping = last_to_first(transform)
    top, bottom = 0, len(transform) - 1
    while pattern:
        symbol, pattern = pattern[-1], pattern[:-1]
        rows = [i for i in range(top, bottom + 1) if transform[i] == symbol]
        if not rows:
            return 0
        top, bottom = mapping[rows[0]], mapping[rows[-1]]
    return bottom - top + 1

Counting in Constant Time

That code scans the band at every step, and the first band is the whole matrix, so a single search can touch every row of a three billion row matrix. Only two facts about the band are ever used: how many copies of the symbol lie above the top of it, and how many lie above the bottom. Both are values of one function, $\textit{count}(\textit{symbol}, i)$, the number of occurrences of the symbol in the first $i$ positions of the last column, and precomputing that function removes the scan.

The other ingredient is $\textit{firstOccurrence}(\textit{symbol})$, the row where the block of rows beginning with that symbol starts. The first column is sorted, so a symbol occupies one block, and the $k$th row of that block is the $k$th occurrence of the symbol in the first column. Combining the two gives both ends of the new band by arithmetic. 

def bw_index(transform):
    symbols = sorted(set(transform))
    count = {symbol: [0] * (len(transform) + 1) for symbol in symbols}
    for i, symbol in enumerate(transform):
        for s in symbols:
            count[s][i + 1] = count[s][i] + (s == symbol)
    first_occurrence, total = {}, 0
    for symbol in symbols:
        first_occurrence[symbol] = total
        total += count[symbol][len(transform)]
    return first_occurrence, count


def bw_range(transform, pattern, index):
    first_occurrence, count = index
    top, bottom = 0, len(transform) - 1
    for symbol in reversed(pattern):
        if symbol not in count:
            return 0, -1
        top = first_occurrence[symbol] + count[symbol][top]
        bottom = first_occurrence[symbol] + count[symbol][bottom + 1] - 1
        if top > bottom:
            return 0, -1
    return top, bottom


def better_bw_matching(transform, pattern, index):
    top, bottom = bw_range(transform, pattern, index)
    return bottom - top + 1

A search now costs $O(|\textit{Pattern}|)$ with a small constant, and it never reads the text. Measured against direct comparison on the same $100$ kb human window, $300$ patterns of length $30$ take $7.13$ seconds by sliding and $0.014$ seconds through the transform, a factor of $509$, and the whole gap is in the algorithm rather than in the language.

Stored plainly, $\textit{count}$ is one integer per symbol per position, which for four symbols and four byte integers is $49.6$ gigabytes for a human genome, four times worse than the suffix array it was meant to replace. It is stored at only every $C$th position instead, and the values in between are recovered by counting forward from the nearest stored row, which costs at most $C$ reads of the transform.

From a Row to a Position

A band of rows answers how many times a pattern occurs and not where, and a read mapper needs where. The suffix array holds exactly that translation, and storing it would undo the saving, so it is stored for one row in $k$ and the rest is recovered by walking. 

def partial_suffix_array(text, k):
    return {i: p for i, p in enumerate(suffix_array(text)) if p % k == 0}


def previous_row(row, transform, index):
    first_occurrence, count = index
    symbol = transform[row]
    return first_occurrence[symbol] + count[symbol][row]


def locate(row, transform, index, partial):
    steps = 0
    while row not in partial:
        row = previous_row(row, transform, index)
        steps += 1
    return partial[row] + steps


def bw_search(pattern, transform, index, partial):
    top, bottom = bw_range(transform, pattern, index)
    return [locate(row, transform, index, partial) for row in range(top, bottom + 1)]

Each step of the walk moves one position earlier in the text, so a row reached after $s$ steps from a stored row holding position $p$ is itself at position $p + s$. The walk stops at the first position divisible by $k$, so it takes at most $k - 1$ steps.

The parts now add up to something that fits. Two bits per nucleotide store the transform, which is $775$ megabytes for a human genome; checkpoints every $128$ positions add $387.5$ megabytes; a partial suffix array holding one position in $32$ adds another $387.5$. The total is about $1.55$ gigabytes, and this is why the read mappers in general use, Bowtie and BWA among them, are built on the transform rather than on the tree or the array.

Approximate Matching

Every search so far has been exact, and reads do not match exactly. A read carries sequencing errors, and a patient's chromosome genuinely differs from the reference at the positions the experiment is looking for, so a read spanning the mutation cannot match the reference by definition. Of the $30{,}000$ simulated reads used at the end of this chapter, $10{,}882$, or $36.3$ percent, occur in the reference exactly. Exact matching throws away two reads in three.

Multiple Approximate Pattern Matching Problem. Given a string $\textit{Text}$, a collection $\textit{Patterns}$, and an integer $d$, find all starting positions where a string from $\textit{Patterns}$ occurs with at most $d$ mismatches.

Theorem. If a pattern occurs at a position with at most $d$ mismatches, and the pattern is cut into $d + 1$ non-empty pieces, then at least one piece occurs exactly at the matching position, at its own offset within the pattern.

The proof is the pigeonhole principle. Each of the at most $d$ mismatched positions lies in exactly one of the $d + 1$ pieces, so the mismatches touch at most $d$ pieces and at least one piece is left with none. That piece agrees with the text symbol for symbol, which is an exact occurrence.

The theorem converts approximate matching into exact matching plus verification, which is the method every read mapper uses. Cut each pattern into $d + 1$ seeds, look each seed up exactly in the transform, and for each place a seed lands, check the whole pattern against the text at the position that seed implies. Seeds long enough to be rare make the check cheap, since a seed of $25$ nucleotides has about $3.1 \times 10^9 / 4^{25}$ chance occurrences in a human genome, which is effectively none. 

def seeds(pattern, d):
    """Cut a pattern into d + 1 pieces, returned with their offsets."""
    edges = [len(pattern) * i // (d + 1) for i in range(d + 2)]
    return [(edges[i], pattern[edges[i]:edges[i + 1]]) for i in range(d + 1)]


def approximate_matching(text, patterns, d, k=1):
    ended = text + '$'
    transform = burrows_wheeler(ended)
    index, partial = bw_index(transform), partial_suffix_array(ended, k)
    positions = []
    for pattern in patterns:
        found = set()
        for offset, seed in seeds(pattern, d):
            for hit in bw_search(seed, transform, index, partial):
                start = hit - offset
                if start < 0 or start + len(pattern) > len(text):
                    continue
                window = text[start:start + len(pattern)]
                if sum(a != b for a, b in zip(window, pattern)) <= d:
                    found.add(start)
        positions += found
    return sorted(positions)

Counting mismatches as the verification step assumes the read differs from the reference by substitutions only. A read carrying an insertion or a deletion is shifted from that point on and fails a mismatch count even though it belongs where the seed says. Replacing the count with alignment from Chapter 5, run in fitting mode so the read is fitted into a window of the reference, scores the placement while allowing gaps. In the run below that recovers $756$ of the $1{,}148$ reads the mismatch count rejected.

BLAST, the Basic Local Alignment Search Tool, is the same method applied to a different problem. Instead of placing many short reads on one genome it takes one query sequence and searches a database of many sequences, so it indexes the query's short words rather than the database, scans for exact word hits, and extends each hit into a local alignment of the kind Chapter 5 computes. It is not implemented here.

Application: Locating the Mutation

The reference is the real one: positions $74{,}960{,}001$ to $75{,}060{,}000$ of human chromosome 10 in assembly GRCh38, a window of $100{,}000$ nucleotides spanning KAT6B, fetched from NCBI as record NC_000010.11. The mutation is a real one: ClinVar record VCV002444621, written NM_012330.4(KAT6B):c.2347C>T (p.Arg783Ter), classified Pathogenic by several submitters with no conflicts and associated with the SBBYS form of Ohdo syndrome. It replaces the C at chromosome 10 position $74{,}981{,}902$ with a T, and the reference base at that position in the fetched sequence is indeed C.

The reads are simulated, and that is the one part of this that is not real. Sequencing data from a patient is not public, so the reads are generated from the reference itself: two copies of the region, one unchanged and one carrying the substitution, sampled at thirty-fold coverage into $30{,}000$ reads of length $100$, from either strand, with each nucleotide misread with probability $0.01$ and two percent of reads carrying a deletion of one to three nucleotides. The result therefore shows that the index and the mapping recover a known heterozygous substitution from data with that error profile. It shows nothing about real error profiles, about mapping into repetitive regions, or about how a variant is judged to be the cause of a disorder.

The transform of the window is built through the suffix array identity, checked against burrows_wheeler and inverse_burrows_wheeler on a prefix, and the reads are mapped by seeds and verification with $d = 3$, each read tried in both orientations and kept only when exactly one placement survives. Exact matching places $10{,}882$ reads, $36.3$ percent. Seeds and verification place $28{,}852$, $96.2$ percent. The pile-up covers $99{,}996$ of the $100{,}000$ positions at a mean depth of $28.9$ reads.

A position is called when at least ten reads cover it and a non-reference nucleotide is supported by at least five of them and by at least a quarter of the column. Across the whole window that rule fires exactly once, at chromosome 10 position $74{,}981{,}902$, where $13$ of $28$ reads read T against the reference C. It is the ClinVar variant, at the fraction a mutation on one of two chromosome copies should have, and the code that found it is the code in this chapter.

The nucleotide it changes matters because of what it does to the protein. Codon 783 of KAT6B reads CGA and codes for arginine; changing that C to T makes it TGA, which is a stop codon, so translation ends there and the protein is cut short at position 783 of 2073. The letters p.Arg783Ter in the ClinVar name say exactly that. One nucleotide out of three billion, recovered by an index that fits in a gigabyte and a half.
