Chapter 3: How Do We Assemble Genomes?

Chapters 1 and 2 searched a genome that was already known. This chapter builds one. The input is a collection of short fragments read off a DNA sample, and the output is the genome they came from. The problem reduces to finding a path in a graph, and the choice of graph decides whether it is tractable.

Reading a Genome in Fragments

No machine reads a chromosome from end to end. Sequencing works on short fragments called reads. The procedure starts from a small tissue or blood sample holding millions of cells, each with its own copy of the genome. A biochemical step breaks that DNA into fragments, and the machine reads the fragments. Because the copies break in different places, the reads overlap.

An earlier technology attacked the same problem differently. DNA arrays, introduced in 1988, tested a sample against every possible k-mer at once and reported which ones were present. They failed for two reasons: the chemical binding between the sample and the array was not reliable enough to trust the answers, and the largest workable $k$ was around $10$, too short to tell apart the repeated stretches genomes contain. Next generation sequencing, from 2005, made whole-genome sequencing practical instead. It produces millions of reads at once, each roughly 100 nucleotides long, at the price of an error rate high enough to matter.

Four properties of real read data complicate the problem:

  • DNA is double stranded, so a read may come from either strand, and which one is not recorded.
  • Coverage is uneven. Some positions are read many times and some not at all.
  • Reads contain errors.
  • Reads are not all the same length.

The String Reconstruction Problem

The idealized problem assumes all four away: every position is covered, no read contains an error, every read has the same length $k$, and every read comes from the same strand.

The k-mer composition of a string is the collection of all of its k-mers, repeats included. 

def composition(text, k):
    return [text[i:i + k] for i in range(len(text) - k + 1)]

String Reconstruction Problem. Given an integer $k$ and a collection of k-mers, find a string whose k-mer composition is that collection.

Reads already in genome order are easy to merge. Consecutive k-mers overlap in $k - 1$ characters, so each one after the first contributes a single new character. 

def path_to_genome(path):
    return path[0] + ''.join(kmer[-1] for kmer in path[1:])

The input, however, is a collection and carries no order. Recovering the order is the whole problem.

The Overlap Graph

Two k-mers can sit next to each other in the genome only if the last $k - 1$ characters of the first equal the first $k - 1$ characters of the second. Take the reads as nodes and draw an edge from $a$ to $b$ when the suffix of $a$ equals the prefix of $b$. This is the overlap graph. 

def overlap_graph(patterns):
    adjacency = {}
    for a in patterns:
        for b in patterns:
            if a != b and a[1:] == b[:-1]:
                adjacency.setdefault(a, []).append(b)
    return adjacency

A string with the given composition corresponds to a path through the overlap graph that visits every node exactly once, a Hamiltonian path. Every read is used, and consecutive reads overlap correctly. Building the graph costs $O(n^2 k)$ for $n$ reads, since every ordered pair is tested.

De Bruijn Graphs

The same information fits in a graph that carries the k-mers on its edges. Each k-mer becomes an edge from its prefix of length $k - 1$ to its suffix of length $k - 1$, and equal $(k-1)$-mers become a single node. This is the de Bruijn graph, named after Nicolaas de Bruijn. 

def de_bruijn(patterns):
    adjacency = {}
    for pattern in patterns:
        adjacency.setdefault(pattern[:-1], []).append(pattern[1:])
    return adjacency

The de Bruijn graph of a string is the graph of its composition, de_bruijn(composition(text, k)). For AAGATTCTCTAC with $k = 4$: 

AAG -> AGA
AGA -> GAT
ATT -> TTC
CTA -> TAC
CTC -> TCT
GAT -> ATT
TCT -> CTA,CTC
TTC -> TCT

Merging equal $(k-1)$-mers is what changes the problem. Every k-mer of the collection is an edge, so a string with the given composition corresponds to a path that uses every edge exactly once, an Eulerian path. Building the graph costs $O(n k)$, since each read is handled once.

Hamiltonian or Eulerian

Both graphs hold the same reads, and for a real genome both have millions of nodes and edges, so their size is not what separates them. The path problem is. Finding an Eulerian path has a polynomial algorithm. Deciding whether a graph has a Hamiltonian path is NP-complete, and no polynomial algorithm is known. Early assemblers used the overlap graph, and the de Bruijn graph replaced it.

Euler's Theorem

A node is balanced when its indegree equals its outdegree, and a graph is balanced when all of its nodes are. A directed graph is strongly connected when every node can be reached from every other.

Euler's Theorem. Every balanced, strongly connected directed graph has an Eulerian cycle.

The proof is constructive, and it is the algorithm. Start at any node and walk along unused edges. Every node is balanced, so a walk that arrives at a node with edges left can always leave again, and the only place it can get stuck is the node it started from, closing a cycle. If that cycle misses some edges, strong connectivity puts an unused outgoing edge at one of the nodes it already passes through. Restart from that node, walk a second cycle through unused edges, and splice it into the first at the shared node. Every round consumes at least one new edge, so the process ends with a cycle that uses all of them.

Finding an Eulerian Cycle

The iterative form keeps a stack. It pushes along unused edges while any remain at the current node, and pops a node into the output once its edges are spent. Reversing the output gives an Eulerian cycle. 

def eulerian_cycle(graph):
    unused = {node: list(edges) for node, edges in graph.items()}
    stack, cycle = [next(iter(graph))], []
    while stack:
        node = stack[-1]
        if unused.get(node):
            stack.append(unused[node].pop())
        else:
            cycle.append(stack.pop())
    return cycle[::-1]

Every edge is pushed once and popped once, so the cost is $O(E)$ for $E$ edges.

From Cycle to Path

A graph with an Eulerian path but no Eulerian cycle is nearly balanced: exactly one node has one more outgoing edge than incoming, and exactly one has one more incoming than outgoing. Adding an edge from the second to the first balances the graph. If the result is strongly connected it has an Eulerian cycle, and cutting that cycle at the added edge leaves an Eulerian path. 

def eulerian_path(graph):
    out_degree = {node: len(edges) for node, edges in graph.items()}
    in_degree = {}
    for edges in graph.values():
        for node in edges:
            in_degree[node] = in_degree.get(node, 0) + 1

    start = end = None
    for node in set(out_degree) | set(in_degree):
        surplus = out_degree.get(node, 0) - in_degree.get(node, 0)
        if surplus == 1:
            start = node
        elif surplus == -1:
            end = node
    if start is None:
        return eulerian_cycle(graph)

    patched = {node: list(edges) for node, edges in graph.items()}
    patched.setdefault(end, []).append(start)
    cycle = eulerian_cycle(patched)[:-1]
    split = next(
        i
        for i in range(len(cycle))
        if cycle[i] == end and cycle[(i + 1) % len(cycle)] == start
    )
    return cycle[split + 1:] + cycle[:split + 1]

Reconstructing a String from its k-mer Composition

The pieces compose into a solution of the String Reconstruction Problem: build the de Bruijn graph of the reads, find an Eulerian path, and spell the string that path traces. 

def string_reconstruction(patterns):
    return path_to_genome(eulerian_path(de_bruijn(patterns)))

The whole procedure is linear in the input, $O(n k)$ for $n$ reads of length $k$. On the 6 reads CTTA, ACCA, TACC, GGCT, GCTT, TTAC it returns GGCTTACCA.

A bacterial chromosome is circular, as Chapter 1 described. The de Bruijn graph of a circular string is balanced, because every $(k-1)$-mer is entered as many times as it is left, so Euler's theorem applies to it as it stands and the genome is spelled by an Eulerian cycle rather than a path. For a circular genome eulerian_cycle replaces eulerian_path and there are no unbalanced nodes to patch. A linear genome is the nearly balanced case: its first $(k-1)$-mer has one extra outgoing edge and its last one has one extra incoming edge.

k-Universal Circular Strings

De Bruijn introduced the graph for a problem with no biology in it. A binary string is k-universal if it contains every binary k-mer exactly once. Read circularly, such a string has length $2^k$, and finding one is string reconstruction over the alphabet $\{0, 1\}$: take all $2^k$ binary k-mers as the composition and find an Eulerian cycle in their de Bruijn graph. 

def k_universal_circular_string(k):
    patterns = [format(i, '0%db' % k) for i in range(2 ** k)]
    cycle = eulerian_cycle(de_bruijn(patterns))
    return path_to_genome(cycle)[:2 ** k]

For $k = 3$ this returns 00111010. Reading it circularly gives 001, 011, 111, 110, 101, 010, 100, 000, which is all eight binary 3-mers. De Bruijn wanted these strings for every $k$, and the graph settles the question: each $(k-1)$-mer has exactly two outgoing edges, one per way of appending a bit, and two incoming edges, one per way of prepending one. The graph is balanced and strongly connected for every $k$, so Euler's theorem guarantees a k-universal string always exists.

Repeats

The String Reconstruction Problem asks for a string with the given composition, not the string. The two differ, and repeats are the reason.

Equal $(k-1)$-mers become one node no matter where in the genome they occur. A stretch that appears twice therefore collapses into one piece of the graph: the node where it begins gains a second outgoing edge and the node where it ends gains a second incoming one. Each way of pairing those edges is a separate Eulerian path, and different pairings spell different strings.

Five characters are enough to see it. AACAA and ACAAC have the same 3-mer composition, AAC, ACA and CAA, so that composition does not determine the string. The ambiguity does not fade with length: TAATGCCATGGGATGTT and TAATGGGATGCCATGTT also share a 3-mer composition.

A repeat shorter than $k - 1$ costs nothing, because it still produces distinct k-mers and distinct nodes. A repeat of length $k - 1$ or more collapses. Raising $k$ therefore resolves more repeats, which is why DNA arrays failed at $k \approx 10$: genomes hold repeated stretches thousands of nucleotides long. Raising $k$ has a ceiling, since a k-mer has to fit inside a read.

Assembling Real Reads

Read Breaking

Real reads are longer than any workable $k$ and are not all the same length. Both problems go away if the reads are not used as units: split every read of length $L$ into its $L - k + 1$ k-mers and assemble those. This is read breaking. 

def read_breaking(reads, k):
    return [kmer for read in reads for kmer in composition(read, k)]

The choice of $k$ is now independent of the read length. The price is information. Which k-mers came from the same read is discarded, and a single wrong character no longer spoils one read but up to $k$ of the k-mers taken from it.

Double Strands, Gaps, and Errors

Double strands. A read comes from one of the two strands and does not say which. Both the read and its reverse complement have to enter the collection, using reverse_complement from Chapter 1. This doubles the edges and admits paths that cross between the two strands.

Gaps in coverage. A region that no read covers leaves no edge across it, so the graph is not strongly connected and Euler's theorem does not apply. There is no Eulerian path to find.

Errors. One wrong character inside a read yields up to $k$ k-mers that occur nowhere in the genome. In the graph they form a short detour that leaves the correct path and rejoins it a few nodes later, called a bubble. Assemblers find bubbles and delete the branch that few reads support.

Edge Multiplicity

An Eulerian path uses every edge exactly once, so the graph has to say how many copies of each edge there are. A stretch of DNA present twice in the genome contributes two copies of each of its edges, and both have to be traversed. de_bruijn takes those counts from its input, one edge per k-mer in the list, which is right when the composition is exact.

Real reads do not give exact counts. How often a k-mer turns up among the reads depends on how many reads happened to cover that position, so the counts have to be turned into multiplicities. Let $c$ be the average number of reads covering a position. A k-mer from a stretch occurring once in the genome shows up about $c$ times, one from a stretch occurring $m$ times shows up about $m c$ times, so dividing an observed count by $c$ and rounding estimates $m$.

The estimate is only as good as the evenness of the coverage, and it is least reliable where it matters most. Repeated stretches are the ones with $m > 1$, and they are also where a wrong multiplicity changes which Eulerian paths exist at all. This is the second cost of uneven coverage: a region with no reads breaks the graph, and a region read too few or too many times corrupts the multiplicities.

Contigs

Even after read breaking and error correction, a de Bruijn graph built from real data has no Eulerian path. Coverage gaps disconnect it, and repeats leave branch points that no quantity of correct reads can resolve. Assembly does not return a chromosome.

It returns contigs: the longest stretches of the genome that the reads pin down unambiguously. In the graph a contig is a path that never branches. It can be extended as long as each node along it has exactly one incoming and one outgoing edge, and it stops at a node where the edges fork, because there the reads do not say which way the genome goes. Producing every contig means finding every maximal non-branching path in the graph.

Call a node 1-in-1-out when its indegree and its outdegree both equal $1$. A path is non-branching when every node strictly inside it is 1-in-1-out, and maximal when it cannot be extended at either end. The contigs are the strings spelled by the maximal non-branching paths.

A maximal non-branching path begins at a node that is not 1-in-1-out, so the paths can be collected by taking each such node in turn and following each of its outgoing edges forward through 1-in-1-out nodes until reaching a node that is not one. One case escapes this: a cycle whose every node is 1-in-1-out contains no starting node, so no walk enters it. A second pass over the nodes no walk visited picks those cycles up. 

def maximal_non_branching_paths(graph):
    out_degree = {node: len(edges) for node, edges in graph.items()}
    in_degree = {}
    for edges in graph.values():
        for node in edges:
            in_degree[node] = in_degree.get(node, 0) + 1
    nodes = set(in_degree) | set(out_degree)

    def internal(node):
        return in_degree.get(node, 0) == 1 and out_degree.get(node, 0) == 1

    paths, visited = [], set()
    for node in nodes:
        if internal(node):
            continue
        for successor in graph.get(node, []):
            path = [node, successor]
            while internal(path[-1]):
                visited.add(path[-1])
                path.append(graph[path[-1]][0])
            paths.append(path)

    for node in nodes:                      # cycles of 1-in-1-out nodes only
        if internal(node) and node not in visited:
            cycle = [node]
            while True:
                visited.add(cycle[-1])
                cycle.append(graph[cycle[-1]][0])
                if cycle[-1] == node:
                    break
            paths.append(cycle)
    return paths

def contigs(patterns):
    return [
        path_to_genome(path)
        for path in maximal_non_branching_paths(de_bruijn(patterns))
    ]

Each edge lies in exactly one maximal non-branching path, so the paths partition the edges and the whole procedure costs $O(V + E)$.

Take AAGATTCTCTAC with $k = 4$, the graph listed earlier. Three of its nodes are not 1-in-1-out: AAG has no incoming edge, TAC has no outgoing edge, and TCT has two of each. The contigs are AAGATTCT, TCTCT and TCTAC, and each one begins or ends at TCT. That 3-mer occurs twice in the string, and the assembly stops exactly where the repeat put a fork in the graph.

Short reads do not produce a chromosome, they produce contigs. A contig ends for one of two reasons. Where no read covered the DNA, the graph has no edge across the gap and there is nothing to continue with. Where a repeat longer than $k$ occurs, the graph branches and the reads give no way to choose between the branches. More short reads fix neither problem. Both need something else: reads long enough to span a repeat in one piece, or a separate experiment that orders the contigs along the chromosome.
