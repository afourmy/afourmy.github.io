Chapter 1: Where in the Genome Does Replication Begin?

This chapter states a biological problem, locating the position in a genome where DNA replication starts, as a string search problem. The algorithms developed here (k-mer counting, pattern matching, approximate search) are used throughout the rest of the course.

DNA: The Basics

DNA is the molecule that encodes the instructions for building and running a cell. It is made of four nucleotides: Adenine (A), Thymine (T), Cytosine (C), and Guanine (G). From a CS perspective, a DNA strand is a string over the alphabet {A, T, C, G}.

DNA is double-stranded: two strands are bonded together. The pairing is fixed by chemistry: A always pairs with T, and C always pairs with G.

The two strands are antiparallel: they run in opposite directions. Each strand has a chemical directionality defined by its ends, called 5' and 3'. By convention, DNA sequences are always written 5' to 3'. So if one strand reads 5'-ATCG-3', the paired strand reads 3'-TAGC-5', which in standard 5'-to-3' notation is CGAT.

To get the complementary strand in 5'-to-3' notation: reverse the original strand, then swap each base with its complement (A↔T, C↔G). This is called the reverse complement. 

COMPLEMENT = {'A': 'T', 'T': 'A', 'C': 'G', 'G': 'C'}

def reverse_complement(pattern):
    return ''.join(COMPLEMENT[b] for b in reversed(pattern))

For example: reverse_complement("ATCGTA") → "TACGAT".

The Origin of Replication

Before a cell divides, it must copy its entire genome. This process is called DNA replication. Each strand of the double helix serves as a template for synthesizing a new complementary strand, producing two identical copies of the original. Watson and Crick noted this in their 1953 landmark paper on DNA structure: "it has not escaped our notice that the specific pairing we have postulated immediately suggests a possible copying mechanism for the genetic material."

Replication does not start at a random position. It begins at a specific region called the origin of replication (ori). A protein called DnaA initiates replication by binding to short sequences near ori called DnaA boxes. In bacteria, DnaA boxes are roughly 9-mers that appear multiple times clustered within a short stretch of DNA near ori.

Understanding ori has practical applications. In gene therapy, a patient is deliberately infected with a viral vector carrying an engineered gene that encodes a therapeutic protein. Such vectors carry their own ori to hijack the host cell's replication machinery, so knowing where and how replication begins is essential for engineering them.

Finding the Origin: Frequent k-mers

The computational question is: given a genome string, find short substrings (k-mers) that appear unusually often in a region. Those are candidate DnaA boxes.

A first primitive: find all positions where a pattern occurs exactly in a text. 

def pattern_match(text, pattern):
    k = len(pattern)
    return [i for i in range(len(text) - k + 1) if text[i:i+k] == pattern]

This is $O(n \cdot k)$ where $n = |text|$. To find the most frequent k-mers, slide a window across the text and count each k-mer in a dictionary: 

def frequent_words_naive(text, k):
    counts = {}
    for i in range(len(text) - k + 1):
        kmer = text[i:i+k]
        counts[kmer] = counts.get(kmer, 0) + 1
    max_count = max(counts.values())
    return [kmer for kmer, c in counts.items() if c == max_count]

This is also $O(n \cdot k)$: there are $n - k + 1$ windows, and slicing each k-mer costs $O(k)$.

An alternative is a frequency array of size $4^k$ instead of a dictionary. Each k-mer is mapped to a unique integer index in $[0,\, 4^k - 1]$ by treating the string as a base-4 number (A=0, C=1, G=2, T=3). This replaces a hash lookup with direct indexing, and makes the encoding of a k-mer as an integer explicit, a representation reused throughout bioinformatics. 

BASE  = {'A': 0, 'C': 1, 'G': 2, 'T': 3}
BASES = 'ACGT'

def kmer_to_index(kmer):
    index = 0
    for base in kmer:
        index = 4 * index + BASE[base]
    return index

def index_to_kmer(index, k):
    kmer = []
    for _ in range(k):
        kmer.append(BASES[index % 4])
        index //= 4
    return ''.join(reversed(kmer))

def frequent_words(text, k):
    freq = [0] * (4 ** k)
    for i in range(len(text) - k + 1):
        freq[kmer_to_index(text[i:i+k])] += 1
    max_count = max(freq)
    return [index_to_kmer(i, k) for i, c in enumerate(freq) if c == max_count]

The cost is memory. The array occupies $O(4^k)$ space, and the final scan over it costs $O(4^k)$ regardless of how short the genome is. Asymptotically this is $O(n \cdot k + 4^k)$, so it is only worthwhile while $4^k$ stays comparable to $n$: at $k = 9$ the array holds 262,144 entries, at $k = 12$ it holds 16 million, and beyond that the dictionary version is faster, since it only stores the k-mers that actually occur.

Important: we must search both strands. A DnaA box on one strand has its reverse complement on the other, and DnaA can bind either. In practice, we count both a k-mer and its reverse complement together.

The Clump Finding Problem

Counting k-mers only helps once we know which stretch of DNA to count them in. Applied to a whole bacterial genome the result is noise: the E. coli genome is 4.6 million nucleotides long and only $4^9 = 262{,}144$ distinct 9-mers exist, so every 9-mer occurs roughly 17 times by chance alone and the most frequent one carries no information about ori. The search has to be restricted to a window short enough that a repeated 9-mer is not explained by chance.

In a real bacterial genome, ori is a region of roughly 500 base pairs in which DnaA boxes cluster tightly. The clump finding problem formalizes this: find all k-mers that appear at least $t$ times within some window of length $L$.

A k-mer forms an $(L, t)$-clump in genome if there exists a window of length $L$ containing at least $t$ occurrences of that k-mer. 

def find_clumps_naive(genome, kmer_length, window_length, min_occurrences):
    clumps = set()
    for window_start in range(len(genome) - window_length + 1):
        window = genome[window_start:window_start + window_length]
        counts = {}
        for offset in range(window_length - kmer_length + 1):
            kmer = window[offset:offset + kmer_length]
            counts[kmer] = counts.get(kmer, 0) + 1
            if counts[kmer] >= min_occurrences:
                clumps.add(kmer)
    return clumps

This naive implementation is $O(n \cdot L \cdot k)$: it rebuilds the count table from scratch for every window. The fix is to keep a single count table and slide the window one position at a time, updating only at the edges: drop the k-mer leaving on the left, add the k-mer entering on the right. Each slide does $O(k)$ work, giving $O(n \cdot k)$ overall. 

def find_clumps(genome, kmer_length, window_length, min_occurrences):
    clumps = set()
    counts = {}
    for kmer_start in range(len(genome) - kmer_length + 1):
        # The k-mer entering on the right of the current window.
        entering = genome[kmer_start:kmer_start + kmer_length]
        counts[entering] = counts.get(entering, 0) + 1

        # Once the window is full, drop the k-mer that fell off the left.
        leaving_start = kmer_start - (window_length - kmer_length)
        if leaving_start > 0:
            leaving = genome[leaving_start - 1:leaving_start - 1 + kmer_length]
            counts[leaving] -= 1

        if counts[entering] >= min_occurrences:
            clumps.add(entering)
    return clumps

On real genomes, clump finding returns thousands of candidates and is not specific enough on its own. The next section provides a complementary approach that narrows down ori directly.

Replication Asymmetry and the Skew

How Replication Works

In bacteria, the chromosome is circular. Replication starts at ori and proceeds in both directions simultaneously, creating two replication forks that travel around the chromosome until they meet at the terminus (ter), roughly opposite ori.

DNA is copied by an enzyme called DNA polymerase, which does not wait for the double helix to fully unwind: it starts synthesizing new DNA at the fork while the strands are still separating. DNA polymerase can only extend a strand in the 5'-to-3' direction. At each fork, one strand (the leading strand) is synthesized continuously in the direction the fork is moving. The other (the lagging strand) must be synthesized in short fragments called Okazaki fragments, going in the direction opposite to fork movement; these fragments are later stitched together by an enzyme called DNA ligase.

The lagging strand template spends much more time single-stranded than the leading strand template, since it waits for the fork to advance before each fragment is copied. When DNA is single-stranded, cytosine (C) spontaneously decays into thymine (T) at a much higher rate (a reaction called deamination, roughly 100 times faster than in double-stranded DNA). So a strand that sits single-stranded for a long time slowly loses its C's.

The mutation only goes one way: C becomes T, and no G is ever created. A strand that spent time single-stranded therefore ends up with a deficit of C, and reading along it, the number of G's exceeds the number of C's.

The available genome sequence is that of one of the two strands, and that single strand plays both roles: because the two forks travel in opposite directions away from ori, the stretch of it between ori and ter is copied as a leading strand, while the stretch between ter and ori serves as the template for a lagging strand and is the one left single-stranded. So the C-deficit falls on one half of the string we are reading and not the other: G leads C in the direction the fork traveled (ori → ter), and the reverse holds on the other half. The G/C imbalance therefore records the direction in which replication ran, and tracking it along the genome locates ori.

These mutations do not damage the genome. Each deamination is rare per replication, most are caught by DNA repair, and natural selection removes the harmful ones that remain. What accumulates over evolutionary time is a small C-deficit at positions where mutations are tolerated: large enough to be measurable by counting bases, too small to affect the cell.

The Skew Diagram

Define the skew at position $i$ as the running value of $\#G - \#C$ up to position $i$: walk along the genome adding $+1$ for each G and $-1$ for each C. On the ori → ter half G dominates, so the running total rises; on the ter → ori half C dominates, so it falls. The running total therefore decreases and then increases: the minimum of the skew marks ori, and the maximum marks ter. 

def skew(genome):
    skew_values, running_skew = [0], 0
    for base in genome:
        if base == 'G':
            running_skew += 1
        elif base == 'C':
            running_skew -= 1
        skew_values.append(running_skew)
    return skew_values

def min_skew(genome):
    skew_values = skew(genome)
    minimum = min(skew_values)
    return [
        position
        for position, value in enumerate(skew_values)
        if value == minimum
    ]

The skew approach is $O(n)$ and provides a fast, independent way to locate the ori region without any k-mer counting.

Approximate Pattern Matching

Real DnaA boxes are not identical copies of a single 9-mer. They have accumulated mutations over evolutionary time, so exact matching misses many occurrences. We need to find patterns that are "close" to a query string.

Hamming Distance

The Hamming distance $d_H(s_1, s_2)$ between two strings of equal length is the number of positions where they differ. 

def hamming_distance(s1, s2):
    return sum(c1 != c2 for c1, c2 in zip(s1, s2))

Approximate Pattern Matching

Find all positions where pattern occurs in text with at most $d$ mismatches. This is pattern_match from earlier with the equality test relaxed into a distance test, and it recovers pattern_match exactly at $d = 0$. 

def approximate_pattern_match(text, pattern, d):
    k = len(pattern)
    return [
        i
        for i in range(len(text) - k + 1)
        if hamming_distance(text[i : i + k], pattern) <= d
    ]

Frequent Words with Mismatches

The final formulation: find k-mers that appear most frequently in the text, counting all approximate occurrences (up to $d$ mismatches). The idea is to generate the neighborhood of each k-mer in the text, i.e. all k-mers within Hamming distance $d$, and accumulate counts across all neighborhood members. 

def neighbors(pattern, max_mismatches):
    neighborhood = {pattern}
    for _ in range(max_mismatches):
        for kmer in list(neighborhood):
            for position in range(len(kmer)):
                for base in "ACGT":
                    neighborhood.add(kmer[:position] + base + kmer[position + 1 :])
    return neighborhood

def frequent_words_with_mismatches(text, k, d):
    counts = {}
    for i in range(len(text) - k + 1):
        for neighbor in neighbors(text[i:i+k], d):
            counts[neighbor] = counts.get(neighbor, 0) + 1
    max_count = max(counts.values())
    return [kmer for kmer, c in counts.items() if c == max_count]

The number of neighbors of a k-mer within Hamming distance $d$ is $\sum_{j=0}^{d} \binom{k}{j} 3^j$. For $k = 9,\, d = 1$: each 9-mer has $1 + 9 \times 3 = 28$ neighbors. Total runtime: $O\!\left(n \cdot \sum_{j=0}^{d}\binom{k}{j} 3^j\right)$.

Frequent Words with Mismatches and Reverse Complements

DnaA binds either strand, so a k-mer and its reverse complement correspond to the same binding site and must be counted together. The function above already accumulates a count per candidate k-mer, so the only change is to add each candidate's count to that of its reverse complement before taking the maximum. 

def frequent_words_with_mismatches_rc(text, k, d):
    counts = {}
    for i in range(len(text) - k + 1):
        for neighbor in neighbors(text[i:i+k], d):
            counts[neighbor] = counts.get(neighbor, 0) + 1

    def total(kmer):
        return counts.get(kmer, 0) + counts.get(reverse_complement(kmer), 0)

    best = max(total(kmer) for kmer in counts)
    return [kmer for kmer in counts if total(kmer) == best]

Both are teaching implementations: enumerating every neighbor does not scale, and real tools replace it with indexed methods (suffix arrays, the FM-index) or probabilistic models.

Locating ori: the Full Pipeline

These components combine into a procedure that takes a bacterial genome and returns candidate DnaA boxes:

  1. Compute the skew and take its minimum. An $O(n)$ scan narrows a genome of millions of nucleotides to a single position.
  2. Extract a window of roughly 500 nucleotides around that position, the expected size of the ori region.
  3. Run frequent_words_with_mismatches_rc on that window with $k = 9$ and $d = 1$. Nine because that is the length of a bacterial DnaA box, one mismatch because real boxes are mutated copies of each other.

Each step is needed because the others are insufficient alone: frequent words over a whole genome returns noise, clump finding returns thousands of candidates, and the skew locates a region without identifying any k-mer inside it. Applied to E. coli, the pipeline returns TTATCCACA together with its reverse complement TGTGGATAA, a known DnaA box.

The pipeline returns candidates, not confirmed DnaA boxes. The skew minimum is approximate, the 500-nucleotide window is an assumption, and a 9-mer that stands out statistically still has to be confirmed experimentally. The pipeline reduces four million positions to a few strings worth testing.

Chapter 2: Which DNA Patterns Play the Role of Molecular Clocks?

Chapter 1 searched a single genome for a pattern that clusters in one place (the ori). This chapter addresses a different problem: finding a pattern that recurs (with variation) exactly once in each of many separate regions. The biological context is the circadian clock.

Biological Motivation: Circadian Clocks and Gene Regulation

Animals, plants, and bacteria have a circadian clock: an internal, roughly 24-hour cycle synchronized with day and night. The clock is encoded in DNA. A small set of circadian genes control it; in plants, three of them are called LHY, CCA1, and TOC1.

A gene is a stretch of DNA coding for a protein. The cell expresses a gene by copying it into RNA, a step called transcription, and building the protein from that copy. Turning a gene on or off means raising or lowering the rate at which it is transcribed.

These genes encode transcription factors: master regulatory proteins that turn other genes on and off. A transcription factor binds to a short, specific stretch of DNA near the gene it controls. That stretch is called a regulatory motif (or transcription factor binding site). A daily cycle of gene activity is produced by transcription factors locating and binding their motifs.

The computational difficulty comes from one property: a regulatory motif is not an exact string. The same factor binds many slightly different sequences. For example, CCA1 binds both AAAAAATCT and AAGAACTCT, which differ at two positions. The target is therefore not a single fixed string but a family of similar strings. Identifying that family is the motif finding problem.

Motif Finding vs. Finding the Ori

Reusing frequent words with mismatches from Chapter 1 does not work well here, for two reasons: one concerns the structure of the signal, the other its cost.

Different signal structure. A DnaA box and a regulatory motif occur in opposite patterns:

  • A DnaA box clumps: it appears many times within one short interval (the ori region of a single genome).
  • A regulatory motif is scattered: it appears just once (perhaps mutated) in each of many different regions - for instance, in the upstream region of every gene that the same factor regulates. No single region contains a clump to detect.

Higher cost. Frequent-words-with-mismatches enumerates the entire neighborhood of every k-mer, and that neighborhood grows rapidly with both the motif length $k$ and the number of allowed mismatches $d$. It does not scale to the long, heavily mutated motifs in this setting. A different approach is required.

The Implanted Motif Problem

We restate the biology as a string problem. The input is a collection of DNA strings (one per region). We look for a k-mer that occurs (with up to $d$ mutations) once in every string.

In code this collection is the list dna. The quantities used throughout the chapter are:

  • $k$: the length of the motif we are searching for.
  • $t$: the number of strings in the collection.
  • $n$: the length of a single string.
  • $d$: the maximum number of mismatches allowed, where a fixed threshold is used.

A k-mer is a $(k, d)$-motif if it appears in every string of the collection with at most $d$ mismatches (Hamming distance $\le d$). The Implanted Motif Problem asks for all $(k, d)$-motifs in a collection.

Brute Force: Motif Enumeration

The brute-force solution is based on one observation: a $(k, d)$-motif must appear with $\le d$ mismatches in the first string too, so it is within Hamming distance $d$ of some k-mer of that string. Every $(k, d)$-motif therefore belongs to the combined $d$-neighborhood of the first string's k-mers. Generate that neighborhood as the candidate set, then keep only the candidates that also occur (with $\le d$ mismatches) in all of the strings. 

def appears_within(text, pattern, d):
    """True if pattern occurs somewhere in text with at most d mismatches."""
    k = len(pattern)
    return any(
        hamming_distance(text[i:i + k], pattern) <= d
        for i in range(len(text) - k + 1)
    )

def motif_enumeration(dna, k, d):
    first = dna[0]
    motifs = set()
    for i in range(len(first) - k + 1):
        for candidate in neighbors(first[i:i + k], d):
            if all(appears_within(text, candidate, d) for text in dna):
                motifs.add(candidate)
    return motifs

This reuses hamming_distance and neighbors from Chapter 1. It is correct, but the neighborhood it builds grows rapidly with $k$ and $d$, the same scaling limitation seen in Chapter 1. The definition is also rigid: a $(k, d)$-motif must stay within $d$ mismatches in every string, so one region with a single extra mutation removes an otherwise valid motif from the results.

The Subtle Motif Problem

A standard benchmark illustrates this limitation. Implant one copy of a 15-mer into each of 10 randomly generated 600-nucleotide strings, and mutate 4 random positions in every copy. This is the Subtle Motif Problem.

The implanted 15-mer is "subtle" because four mutations out of fifteen is a high mutation rate: two implanted copies may differ at up to 8 positions, the motif is usually not the most frequent k-mer in the data, and motif_enumeration with $k = 15$, $d = 4$ generates a neighborhood far too large to enumerate. A usable method must handle this level of noise without relying on a fixed mismatch threshold.

Scoring a Set of Motifs

The formulation changes here. Instead of searching for a pattern, we choose one k-mer from each string and measure how similar the chosen k-mers are to one another. A good choice produces columns dominated by a single nucleotide; a poor choice produces columns close to uniform. Expressing this similarity as a single number turns motif finding into an optimization problem.

Stack the $t$ chosen k-mers as the rows of a $t \times k$ motif matrix, then read it column by column. Take this example with $t = 4$ and $k = 5$: 

    A C G T A
    A C G C A
    A T G T A
    A C T T A

The count matrix has 4 rows (one per nucleotide) and $k$ columns (one per position); entry $(i, j)$ is how many times nucleotide $i$ appears in column $j$: 

       1   2   3   4   5
   A   4   0   0   0   4
   C   0   3   0   1   0
   G   0   0   3   0   0
   T   0   1   1   3   0

The profile matrix divides each count by $t$, giving the frequency $P_{ij}$ of nucleotide $i$ in column $j$ (every column sums to 1): 

        1      2      3      4      5
   A  1.00   0.00   0.00   0.00   1.00
   C  0.00   0.75   0.00   0.25   0.00
   G  0.00   0.00   0.75   0.00   0.00
   T  0.00   0.25   0.25   0.75   0.00

The consensus string takes the most frequent nucleotide in each column (here, ACGTA). It is the candidate regulatory motif for these regions.

Finally, the score measures disagreement: in each column, count the nucleotides that are not the most frequent one, and sum across columns. Columns 1 and 5 are uniform; columns 2, 3, and 4 each contain one differing letter, so the score is $0 + 1 + 1 + 1 + 0 = 3$. A fully conserved motif scores 0, and the more the chosen k-mers differ, the higher the score. The goal is to minimize it.

The four quantities translate directly into code:

NUCLEOTIDES = "ACGT"

def count_matrix(motifs):
    k = len(motifs[0])
    counts = {base: [0] * k for base in NUCLEOTIDES}
    for motif in motifs:
        for position, base in enumerate(motif):
            counts[base][position] += 1
    return counts

def profile_matrix(motifs):
    t = len(motifs)
    counts = count_matrix(motifs)
    return {base: [value / t for value in row] for base, row in counts.items()}

def consensus(motifs):
    counts = count_matrix(motifs)
    return ''.join(
        max(NUCLEOTIDES, key=lambda base: counts[base][position])
        for position in range(len(motifs[0]))
    )

def score(motifs):
    counts = count_matrix(motifs)
    t = len(motifs)
    return sum(
        t - max(counts[base][position] for base in NUCLEOTIDES)
        for position in range(len(motifs[0]))
    )

The Motif Finding Problem

Scoring lets us restate the goal without ever mentioning $d$:

Motif Finding Problem. Given a collection of DNA strings, choose one k-mer from each string so that the resulting motif matrix has the minimum possible score.

This formulation has no mismatch threshold $d$; it specifies a single quantity to minimize. Solving it by brute force is still expensive. Suppose each of the $t$ strings has length $n$. Each string offers $n - k + 1$ possible k-mers, and we pick one per string independently, giving $(n - k + 1)^t$ candidate motif matrices. Scoring one matrix costs about $k \cdot t$ steps, and since $k \ll n$ the total cost is $O(k \cdot t \cdot n^t)$. The $n^t$ term makes the cost exponential in the number of strings $t$, which is impractical. 

from itertools import product

def brute_force_motif_search(dna, k):
    kmers_per_string = [
        [text[i:i + k] for i in range(len(text) - k + 1)]
        for text in dna
    ]
    best_motifs, best_score = None, float('inf')
    for motifs in product(*kmers_per_string):   # (n - k + 1) ** t combinations
        current_score = score(list(motifs))
        if current_score < best_score:
            best_motifs, best_score = list(motifs), current_score
    return best_motifs

The Median String Problem

The score counts, column by column, the entries that differ from the most frequent nucleotide of their column. The same entries can be counted row by row. The most frequent nucleotide of column $j$ is the $j$-th letter of the consensus, so the entries counted in row $i$ are the positions where $\text{Motif}_i$ differs from the consensus, and there are $d_H(\text{Consensus}(\text{Motifs}),\ \text{Motif}_i)$ of them. Summing over rows instead of columns:

$\text{Score}(\text{Motifs}) = \sum_{i=1}^{t} d_H(\text{Consensus}(\text{Motifs}),\ \text{Motif}_i)$

The score is now a function of one string. That allows the roles to be reversed: fix a k-mer $\text{Pattern}$ first, then choose the motifs that fit it. In each string the best choice is the k-mer closest to $\text{Pattern}$, which gives the distance from a k-mer to a whole collection:

$d(\text{Pattern}, \text{Dna}) = \sum_{\text{text} \,\in\, \text{Dna}} \ \min_{\text{k-mer} \,\in\, \text{text}} d_H(\text{Pattern},\ \text{k-mer})$

Minimizing $d(\text{Pattern}, \text{Dna})$ over all k-mers gives the same value as minimizing the score over all choices of motifs. For any motifs, $\text{Score}(\text{Motifs}) \ge d(\text{Consensus}(\text{Motifs}), \text{Dna})$, because each term of the sum is at least the smallest distance available in its string. Conversely, given any $\text{Pattern}$, take the closest k-mer in each string; the consensus of those motifs minimizes the sum of distances to them, so their score is at most $d(\text{Pattern}, \text{Dna})$. Neither quantity can be smaller than the other.

Median String Problem. Given a collection of DNA strings and an integer $k$, find a k-mer $\text{Pattern}$ minimizing $d(\text{Pattern}, \text{Dna})$. Such a k-mer is called a median string.

This changes the search space. Brute force ranged over the $(n - k + 1)^t$ ways of choosing motifs; the median string ranges over the $4^k$ k-mers. The motif length $k$ is fixed by the biology, while $t$ grows with the amount of data available. 

def distance_to_strings(pattern, dna):
    k = len(pattern)
    return sum(
        min(
            hamming_distance(pattern, text[i:i + k])
            for i in range(len(text) - k + 1)
        )
        for text in dna
    )

def median_string(dna, k):
    best_pattern, best_distance = None, float('inf')
    for index in range(4 ** k):
        pattern = index_to_kmer(index, k)
        distance = distance_to_strings(pattern, dna)
        if distance < best_distance:
            best_pattern, best_distance = pattern, distance
    return best_pattern

This reuses hamming_distance and index_to_kmer from Chapter 1. Computing $d(\text{Pattern}, \text{Dna})$ costs $O(n \cdot t \cdot k)$, so the total is $O(4^k \cdot n \cdot t \cdot k)$, exponential in the motif length rather than in the number of strings. It returns an exact minimizer, and it is usable for small $k$. At $k = 15$ there are $4^{15} \approx 1.07 \times 10^9$ candidate strings, so the Subtle Motif Problem is out of reach. The three algorithms that follow drop the guarantee of reaching the minimum in exchange for running at the motif lengths that occur in real data.

Scoring a k-mer with a Profile: the Most Probable k-mer

Both algorithms that follow rely on one new tool. So far a profile has been used to summarize a chosen set of motifs. It can also be used in the other direction, as a predictive model that measures how well an arbitrary k-mer fits it.

Treat each column of the profile as the probability of seeing each nucleotide at that position, and assume the positions are independent. The probability of a k-mer given a profile is then the product of the column frequencies of its letters. For a k-mer with letters $a_1 a_2 \cdots a_k$:

$\Pr(\text{k-mer} \mid \text{Profile}) = \prod_{j=1}^{k} \text{Profile}(a_j,\ j)$

Using the profile from the previous section, the consensus ACGTA scores $1.00 \times 0.75 \times 0.75 \times 0.75 \times 1.00 = 0.42$, the highest of any 5-mer. Any k-mer that disagrees with the consensus scores lower, because it must pick up a smaller frequency in at least one column.

The profile-most-probable k-mer in a string is the k-mer that maximizes this probability: the string's single best candidate for the motif the profile describes. 

def probability(kmer, profile):
    prob = 1.0
    for position, base in enumerate(kmer):
        prob *= profile[base][position]
    return prob

def profile_most_probable_kmer(text, k, profile):
    best_kmer, best_prob = text[:k], -1.0
    for i in range(len(text) - k + 1):
        kmer = text[i:i + k]
        prob = probability(kmer, profile)
        if prob > best_prob:
            best_kmer, best_prob = kmer, prob
    return best_kmer

Ties are broken in favor of the first occurrence.

Greedy Motif Search

A greedy algorithm builds a solution one piece at a time, and at every step it commits to the choice that looks best at that moment, never going back to revise it. It is the paradigm behind algorithms such as Huffman coding and Dijkstra's shortest paths. It gives up the guarantee of reaching the global optimum in exchange for speed.

Greedy motif search builds the motif set one string at a time:

  • Pick a k-mer from the first string as a seed. It is the only row of a one-row motif matrix, and its profile is the first estimate of the motif.
  • Move to the second string and select its profile-most-probable k-mer: the k-mer that best fits the current profile. Add it. The profile is now built from two k-mers instead of one.
  • Continue down the list of strings. Each new string contributes the k-mer that best fits the profile built from all of the previously chosen k-mers.

After the last string we have one complete set of $t$ motifs. Its quality depends entirely on the seed, so we run the whole process once for every k-mer of the first string and keep the lowest-scoring result. 

def greedy_motif_search(dna, k):
    best_motifs = [text[:k] for text in dna]
    first = dna[0]
    for i in range(len(first) - k + 1):
        motifs = [first[i:i + k]]
        for text in dna[1:]:
            profile = profile_matrix(motifs)
            motifs.append(profile_most_probable_kmer(text, k, profile))
        if score(motifs) < score(best_motifs):
            best_motifs = motifs
    return best_motifs

This is polynomial, roughly $O(n^2 \cdot k \cdot t)$ for $t$ strings of length $n$, compared to the exponential cost of brute force. The weakness is inherent to the greedy approach: an early k-mer chosen from a profile built on very little evidence constrains every later choice, and the algorithm never revisits it.

The Zero Problem and Pseudocounts

There is a flaw in scoring k-mers with a raw profile. When only a few motifs have been chosen, many profile entries are exactly $0$, for nucleotides that have not yet appeared in a column. Because the probability of a k-mer is a product, a single $0$ makes the entire value $0$.

Take the profile from before, whose consensus is ACGTA. The k-mer GCGTA differs from the consensus at only the first position, yet column 1 has frequency $0$ for G, so $\Pr(\texttt{GCGTA} \mid \text{Profile}) = 0$. A k-mer matching four columns out of five gets the same probability as one matching none, so the information in those four columns is discarded. This happens precisely when the profile is built from few motifs, as in both algorithms here.

The extreme case occurs at the first step of greedy motif search. Its seed profile is built from a single k-mer, so every column contains one entry equal to $1$ and three equal to $0$, and any k-mer that is not character-for-character identical to the seed has probability $0$. Every candidate in the second string is therefore tied at zero, profile_most_probable_kmer falls back on its tie-breaking rule, and the second string contributes its first k-mer: a choice made by position, carrying no information about the motif at all.

The fix is Laplace's rule of succession: add a pseudocount of $1$ to every entry of the count matrix before dividing. Each column gains four extra observations, so the frequencies use a denominator of $t + 4$. No entry is ever $0$, so a single unpopular letter lowers a k-mer's probability instead of forcing it to zero. 

def profile_with_pseudocounts(motifs):
    t = len(motifs)
    counts = count_matrix(motifs)
    return {
        base: [(value + 1) / (t + 4) for value in row]
        for base, row in counts.items()
    }

With it, GCGTA above receives column-1 frequency $(0 + 1) / (4 + 4) = 0.125$ and a small but nonzero probability. Both greedy and randomized motif search use this pseudocounted profile in place of the raw one. In greedy_motif_search that is a one-line substitution of profile_with_pseudocounts for profile_matrix, and it changes the answer outright: on a five-string sample set the raw version selects CAG, CAG, CAA, CAA, CAA and the pseudocounted version selects TTC, ATC, TTC, ATC, TTC, an entirely different motif. Both happen to score 2 on input this small; the gap appears on data long enough for the early degenerate choices to matter.

Randomized Motif Search

Randomized motif search rests on a circular relationship:

  • given the motifs, computing the profile is easy;
  • given the profile, finding the motifs is easy (take the profile-most-probable k-mer in each string).

Neither is available at the start. The algorithm begins from a guess: choose one k-mer at random from each string, then alternate the two steps. Build a profile from the current motifs, use it to re-select the motifs, and repeat. Each pass replaces the motif set with one that fits its own profile better, so the score never rises. The search stops when a pass fails to improve it. 

import random

def motifs_from_profile(profile, dna, k):
    return [profile_most_probable_kmer(text, k, profile) for text in dna]

def random_motifs(dna, k):
    motifs = []
    for text in dna:
        start = random.randint(0, len(text) - k)
        motifs.append(text[start:start + k])
    return motifs

def randomized_motif_search(dna, k):
    motifs = random_motifs(dna, k)
    best_motifs = motifs
    while True:
        profile = profile_with_pseudocounts(motifs)
        motifs = motifs_from_profile(profile, dna, k)
        if score(motifs) < score(best_motifs):
            best_motifs = motifs
        else:
            return best_motifs

Random k-mers produce a profile that is nearly, but not exactly, uniform. If a few of them overlap the true motif, the profile assigns slightly higher frequencies to the nucleotides of that motif, which makes the re-selection step pick better-matching k-mers in the other strings, which in turn increases those frequencies further. The process amplifies whatever signal the starting set contains.

A single run usually converges to a poor local optimum, because a random start rarely contains any real signal. One run is cheap, so the algorithm is run thousands of times from independent random starts and the best result is kept. With enough starts, at least one begins close enough to the true motif to converge to it. The same structure, alternating two cheap steps from many random starts, is used by clustering methods such as k-means. 

def best_over_many_runs(dna, k, runs=1000):
    best_motifs = randomized_motif_search(dna, k)
    for _ in range(runs - 1):
        candidate = randomized_motif_search(dna, k)
        if score(candidate) < score(best_motifs):
            best_motifs = candidate
    return best_motifs

Gibbs Sampling

Randomized motif search replaces all $t$ motifs at every iteration. A motif that is already correct is discarded together with the rest whenever the new profile points elsewhere in its string, so a run can lose ground it has gained.

Gibbs sampling changes one motif per iteration. Pick a string at random, build the profile from the other $t - 1$ motifs, and replace only that string's motif. The replacement is not the profile-most-probable k-mer: each k-mer of the string is drawn at random with probability proportional to its probability under the profile. Always taking the maximum makes the step deterministic once the profile is fixed, and the search settles into the nearest local optimum. Drawing at random lets a lower-scoring k-mer be picked from time to time, which is what moves the search away from that optimum. 

def weighted_random_kmer(text, k, profile):
    kmers = [text[i:i + k] for i in range(len(text) - k + 1)]
    weights = [probability(kmer, profile) for kmer in kmers]
    return random.choices(kmers, weights=weights)[0]

def gibbs_sampler(dna, k, iterations):
    motifs = random_motifs(dna, k)
    best_motifs = motifs
    for _ in range(iterations):
        i = random.randrange(len(dna))
        profile = profile_with_pseudocounts(motifs[:i] + motifs[i + 1:])
        motifs = motifs[:i] + [weighted_random_kmer(dna[i], k, profile)] + motifs[i + 1:]
        if score(motifs) < score(best_motifs):
            best_motifs = motifs
    return best_motifs

Pseudocounts are required here rather than merely useful. With a raw profile most k-mers of the string would have weight $0$, and the draw would be restricted to those matching every column of a profile built from $t - 1$ motifs.

The score can rise from one iteration to the next, which is what allows the escape from a local optimum. The loop therefore cannot stop at the first step that fails to improve, as randomized motif search does; it runs a fixed number of iterations and tracks the best motif set seen. Each iteration costs $O(n \cdot k)$. A single run still ends in a local optimum, so Gibbs sampling is restarted many times as well.

Application: the Evening Element

Collect the upstream regions of the genes a plant activates at dusk and run the search over them. It returns AAAATATCT, known as the evening element. It was confirmed experimentally: removing it from those upstream regions abolishes the daily rhythm of the genes it precedes.

The Implanted Motif Problem has an exact answer and an algorithm that provably finds it, but that algorithm is unusable at realistic mutation rates. It was replaced by an objective, minimizing the score. The median string minimizes that objective exactly, but at a cost of $4^k$, which rules out the motif lengths found in real data. Greedy motif search, randomized motif search, and Gibbs sampling optimize the same objective with no guarantee of reaching the minimum. This is the usual situation in bioinformatics: the formulation that matches the biology is intractable, so the practical algorithm returns a candidate that then has to be tested experimentally.

Chapter 3: How Do We Assemble Genomes?

Chapters 1 and 2 searched a genome that was already known. This chapter builds one. The input is a collection of short fragments read off a DNA sample, and the output is the genome they came from. The problem reduces to finding a path in a graph, and the choice of graph decides whether it is tractable.

Reading a Genome in Fragments

No machine reads a chromosome from end to end. Sequencing works on short fragments called reads. The procedure starts from a small tissue or blood sample holding millions of cells, each with its own copy of the genome. A biochemical step breaks that DNA into fragments, and the machine reads the fragments. Because the copies break in different places, the reads overlap.

An earlier technology attacked the same problem differently. DNA arrays, introduced in 1988, tested a sample against every possible k-mer at once and reported which ones were present. They failed for two reasons: the chemical binding between the sample and the array was not reliable enough to trust the answers, and the largest workable $k$ was around $10$, too short to tell apart the repeated stretches genomes contain. Next generation sequencing, from 2005, made whole-genome sequencing practical instead. It produces millions of reads at once, each roughly 100 nucleotides long, at the price of an error rate high enough to matter.

Four properties of real read data complicate the problem:

  • DNA is double stranded, so a read may come from either strand, and which one is not recorded.
  • Coverage is uneven. Some positions are read many times and some not at all.
  • Reads contain errors.
  • Reads are not all the same length.

The String Reconstruction Problem

The idealized problem assumes all four away: every position is covered, no read contains an error, every read has the same length $k$, and every read comes from the same strand.

The k-mer composition of a string is the collection of all of its k-mers, repeats included. 

def composition(text, k):
    return [text[i:i + k] for i in range(len(text) - k + 1)]

String Reconstruction Problem. Given an integer $k$ and a collection of k-mers, find a string whose k-mer composition is that collection.

Reads already in genome order are easy to merge. Consecutive k-mers overlap in $k - 1$ characters, so each one after the first contributes a single new character. 

def path_to_genome(path):
    return path[0] + ''.join(kmer[-1] for kmer in path[1:])

The input, however, is a collection and carries no order. Recovering the order is the whole problem.

The Overlap Graph

Two k-mers can sit next to each other in the genome only if the last $k - 1$ characters of the first equal the first $k - 1$ characters of the second. Take the reads as nodes and draw an edge from $a$ to $b$ when the suffix of $a$ equals the prefix of $b$. This is the overlap graph. 

def overlap_graph(patterns):
    adjacency = {}
    for a in patterns:
        for b in patterns:
            if a != b and a[1:] == b[:-1]:
                adjacency.setdefault(a, []).append(b)
    return adjacency

A string with the given composition corresponds to a path through the overlap graph that visits every node exactly once, a Hamiltonian path. Every read is used, and consecutive reads overlap correctly. Building the graph costs $O(n^2 k)$ for $n$ reads, since every ordered pair is tested.

De Bruijn Graphs

The same information fits in a graph that carries the k-mers on its edges. Each k-mer becomes an edge from its prefix of length $k - 1$ to its suffix of length $k - 1$, and equal $(k-1)$-mers become a single node. This is the de Bruijn graph, named after Nicolaas de Bruijn. 

def de_bruijn(patterns):
    adjacency = {}
    for pattern in patterns:
        adjacency.setdefault(pattern[:-1], []).append(pattern[1:])
    return adjacency

The de Bruijn graph of a string is the graph of its composition, de_bruijn(composition(text, k)). For AAGATTCTCTAC with $k = 4$: 

AAG -> AGA
AGA -> GAT
ATT -> TTC
CTA -> TAC
CTC -> TCT
GAT -> ATT
TCT -> CTA,CTC
TTC -> TCT

Merging equal $(k-1)$-mers is what changes the problem. Every k-mer of the collection is an edge, so a string with the given composition corresponds to a path that uses every edge exactly once, an Eulerian path. Building the graph costs $O(n k)$, since each read is handled once.

Hamiltonian or Eulerian

Both graphs hold the same reads, and for a real genome both have millions of nodes and edges, so their size is not what separates them. The path problem is. Finding an Eulerian path has a polynomial algorithm. Deciding whether a graph has a Hamiltonian path is NP-complete, and no polynomial algorithm is known. Early assemblers used the overlap graph, and the de Bruijn graph replaced it.

Euler's Theorem

A node is balanced when its indegree equals its outdegree, and a graph is balanced when all of its nodes are. A directed graph is strongly connected when every node can be reached from every other.

Euler's Theorem. Every balanced, strongly connected directed graph has an Eulerian cycle.

The proof is constructive, and it is the algorithm. Start at any node and walk along unused edges. Every node is balanced, so a walk that arrives at a node with edges left can always leave again, and the only place it can get stuck is the node it started from, closing a cycle. If that cycle misses some edges, strong connectivity puts an unused outgoing edge at one of the nodes it already passes through. Restart from that node, walk a second cycle through unused edges, and splice it into the first at the shared node. Every round consumes at least one new edge, so the process ends with a cycle that uses all of them.

Finding an Eulerian Cycle

The iterative form keeps a stack. It pushes along unused edges while any remain at the current node, and pops a node into the output once its edges are spent. Reversing the output gives an Eulerian cycle. 

def eulerian_cycle(graph):
    unused = {node: list(edges) for node, edges in graph.items()}
    stack, cycle = [next(iter(graph))], []
    while stack:
        node = stack[-1]
        if unused.get(node):
            stack.append(unused[node].pop())
        else:
            cycle.append(stack.pop())
    return cycle[::-1]

Every edge is pushed once and popped once, so the cost is $O(E)$ for $E$ edges.

From Cycle to Path

A graph with an Eulerian path but no Eulerian cycle is nearly balanced: exactly one node has one more outgoing edge than incoming, and exactly one has one more incoming than outgoing. Adding an edge from the second to the first balances the graph. If the result is strongly connected it has an Eulerian cycle, and cutting that cycle at the added edge leaves an Eulerian path. 

def eulerian_path(graph):
    out_degree = {node: len(edges) for node, edges in graph.items()}
    in_degree = {}
    for edges in graph.values():
        for node in edges:
            in_degree[node] = in_degree.get(node, 0) + 1

    start = end = None
    for node in set(out_degree) | set(in_degree):
        surplus = out_degree.get(node, 0) - in_degree.get(node, 0)
        if surplus == 1:
            start = node
        elif surplus == -1:
            end = node
    if start is None:
        return eulerian_cycle(graph)

    patched = {node: list(edges) for node, edges in graph.items()}
    patched.setdefault(end, []).append(start)
    cycle = eulerian_cycle(patched)[:-1]
    split = next(
        i
        for i in range(len(cycle))
        if cycle[i] == end and cycle[(i + 1) % len(cycle)] == start
    )
    return cycle[split + 1:] + cycle[:split + 1]

Reconstructing a String from its k-mer Composition

The pieces compose into a solution of the String Reconstruction Problem: build the de Bruijn graph of the reads, find an Eulerian path, and spell the string that path traces. 

def string_reconstruction(patterns):
    return path_to_genome(eulerian_path(de_bruijn(patterns)))

The whole procedure is linear in the input, $O(n k)$ for $n$ reads of length $k$. On the 6 reads CTTA, ACCA, TACC, GGCT, GCTT, TTAC it returns GGCTTACCA.

k-Universal Circular Strings

De Bruijn introduced the graph for a problem with no biology in it. A binary string is k-universal if it contains every binary k-mer exactly once. Read circularly, such a string has length $2^k$, and finding one is string reconstruction over the alphabet $\{0, 1\}$: take all $2^k$ binary k-mers as the composition and find an Eulerian cycle in their de Bruijn graph. 

def k_universal_circular_string(k):
    patterns = [format(i, '0%db' % k) for i in range(2 ** k)]
    cycle = eulerian_cycle(de_bruijn(patterns))
    return path_to_genome(cycle)[:2 ** k]

For $k = 3$ this returns 00111010. Reading it circularly gives 001, 011, 111, 110, 101, 010, 100, 000, which is all eight binary 3-mers. De Bruijn wanted these strings for every $k$, and the graph settles the question: each $(k-1)$-mer has exactly two outgoing edges, one per way of appending a bit, and two incoming edges, one per way of prepending one. The graph is balanced and strongly connected for every $k$, so Euler's theorem guarantees a k-universal string always exists.

Repeats

The String Reconstruction Problem asks for a string with the given composition, not the string. The two differ, and repeats are the reason.

Equal $(k-1)$-mers become one node no matter where in the genome they occur. A stretch that appears twice therefore collapses into one piece of the graph: the node where it begins gains a second outgoing edge and the node where it ends gains a second incoming one. Each way of pairing those edges is a separate Eulerian path, and different pairings spell different strings.

Five characters are enough to see it. AACAA and ACAAC have the same 3-mer composition, AAC, ACA and CAA, so that composition does not determine the string. The ambiguity does not fade with length: TAATGCCATGGGATGTT and TAATGGGATGCCATGTT also share a 3-mer composition.

A repeat shorter than $k - 1$ costs nothing, because it still produces distinct k-mers and distinct nodes. A repeat of length $k - 1$ or more collapses. Raising $k$ therefore resolves more repeats, which is why DNA arrays failed at $k \approx 10$: genomes hold repeated stretches thousands of nucleotides long. Raising $k$ has a ceiling, since a k-mer has to fit inside a read.

Assembling Real Reads

Read Breaking

Real reads are longer than any workable $k$ and are not all the same length. Both problems go away if the reads are not used as units: split every read of length $L$ into its $L - k + 1$ k-mers and assemble those. This is read breaking. 

def read_breaking(reads, k):
    return [kmer for read in reads for kmer in composition(read, k)]

The choice of $k$ is now independent of the read length. The price is information. Which k-mers came from the same read is discarded, and a single wrong character no longer spoils one read but up to $k$ of the k-mers taken from it.

Double Strands, Gaps, and Errors

Double strands. A read comes from one of the two strands and does not say which. Both the read and its reverse complement have to enter the collection, using reverse_complement from Chapter 1. This doubles the edges and admits paths that cross between the two strands.

Gaps in coverage. A region that no read covers leaves no edge across it, so the graph is not strongly connected and Euler's theorem does not apply. There is no Eulerian path to find.

Errors. One wrong character inside a read yields up to $k$ k-mers that occur nowhere in the genome. In the graph they form a short detour that leaves the correct path and rejoins it a few nodes later, called a bubble. Assemblers find bubbles and delete the branch that few reads support.

Contigs

Even after read breaking and error correction, a de Bruijn graph built from real data has no Eulerian path. Coverage gaps disconnect it, and repeats leave branch points that no quantity of correct reads can resolve. Assembly does not return a chromosome.

It returns contigs: the longest stretches of the genome that the reads pin down unambiguously. In the graph a contig is a path that never branches. It can be extended as long as each node along it has exactly one incoming and one outgoing edge, and it stops at a node where the edges fork, because there the reads do not say which way the genome goes. Producing every contig means finding every maximal non-branching path in the graph.

Short reads do not produce a chromosome, they produce contigs. A contig ends for one of two reasons. Where no read covered the DNA, the graph has no edge across the gap and there is nothing to continue with. Where a repeat longer than $k$ occurs, the graph branches and the reads give no way to choose between the branches. More short reads fix neither problem. Both need something else: reads long enough to span a repeat in one piece, or a separate experiment that orders the contigs along the chromosome.
